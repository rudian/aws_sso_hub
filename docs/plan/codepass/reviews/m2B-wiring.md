## A2-02 · Terminal sessions and the data path

Accepted deviations:

- No bindings regenerated: the service is not registered yet, so the generator would not produce TerminalRead and TerminalPing. A2-W regenerates after registering.
- The event constant EventTerminalPing sits in internal/api/terminal.go, not in api/events.go, to keep to my Owns list. Its RegisterEvent line is A2-W's.
- Start, Stop, Release and Status are Go-only on terminal.Manager; the bound service has only Read, Write and Resize, so the page can never start a program. Read returns (api.TerminalRead, error) and Resize returns error, as other services do; the error is non-nil only for bad base64 or bad dimensions, never for an unknown or ended session.
- done means the terminal ended (the pty Read returned EOF) and everything was read, not just that the root process exited. A session with a setsid background process holding the terminal stays not-done on macOS. Stop forces the session ended after 3 s if the terminal does not end, and later output is dropped.
- The log can hold up to about cap + cap/8 + cap/16 bytes (about 18.5 MB at the 16 MB default) before a trim, because the trim may start at a clear or alt-screen entry up to cap/8 before the ideal cut. Memory stays near the cap and bounded, unlike the spike's 2x.
- The environment is the app's own environment minus a deny list, not a pure allow list. It drops AWSSSOHUB_*, WAILS_*, CODEPASS_*, TERM, COLORTERM, PWD and OLDPWD, and adds TERM, COLORTERM and a UTF-8 LANG. Extra variables override by name, but AWSSSOHUB_* and WAILS_* are also dropped from extras. I chose this so Windows tools, which have no login shell to restore PATH and the like, still work. The proxy variables simply carry over.
- Mode 2026 (synchronized output) is not tracked. A prologue that left it set could freeze a fresh terminal. The spike tracked it.
- Not done: the Go-side vim full-replay and replay-after-gap screen comparison. Go has no terminal emulator here. The Go tests prove the prologue and the cut points, and a property test shows prologue plus retained data reproduces the live mode state. Screen equality belongs to the xterm side (A2-07) and the manual check below.
